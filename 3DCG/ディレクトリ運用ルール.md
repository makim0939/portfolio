# 3DCG作成　ディレクトリ運用ルール

## ファイルの置き場所

**アセットとスクリプトは別の場所にある。**

| 種類 | 置き場所 | 版管理 |
|---|---|---|
| `.blend`、テクスチャ、参考資料、`.glb` | iCloud Drive の `Portfolio2025/3DCG/` | なし |
| スクリプト、このルール文書 | ポートフォリオサイトのリポジトリ `3DCG/` | git |

アセットをリポジトリに置かないのは、**リポジトリが公開されており、3Dモデルの
無断利用や転売のリスクがある**ため。スクリプトはテキストなので公開して問題なく、
むしろ制作過程の記録として価値がある。

スクリプトからアセットを参照するパスは `Scripts/lib/paths.py` が解決する。
環境変数 `PORTFOLIO_3DCG` で差し替えられる。

## ディレクトリ構成

iCloud 側（アセット）:

``` markdown
3DCG/
├── Objects/：個々のオブジェクトのマスター。
│   ├── Avatar/
│   │   └── Avatar.blend        リグとアニメーションもここに同居する
│   ├── Desk/
│   │   └── Desk.blend
│   └── Chair/
│       └── Chair.blend
├── Textures/：テクスチャ編集用のファイル、画像ファイル。
│   ├── Floor/
│   │   └── Albedo.png
│   ├── MainFurniture/
│   └── Portfolio2025Texture.clip
├── Out/：次工程の入力とする`.glb`など。
│   └── Tmp/
├── Reference/：参考資料。
├── PlayGround/：試作・練習用のファイル。
├── Tmp/：一時的なバックアップなど。
└── Portfolio2025-<シーン名>.blend：オブジェクトを組み合わせて作るシーン。
```

リポジトリ側（スクリプト）:

``` markdown
3DCG/
├── Scripts/
│   ├── lib/                    共通ライブラリ・検証ツール
│   ├── Objects/                オブジェクトを生成するスクリプト
│   ├── Motion/                 モーションを作るスクリプト
│   └── Export/                 glb を書き出すスクリプト
└── ディレクトリ運用ルール.md
```

## 運用ルール

### オブジェクト管理

- 個々のオブジェクトのマスターを`Objects/`に配置する。
- オブジェクトの編集は必ずオブジェクトのマスターで行い、シーンでは行わない。
- シーンからは、オブジェクトをリンクして使用する。
- シーンに配置するオブジェクトは必ず`Objects/`にマスターを持つ。
- 1ファイルに1オブジェクトとする。
- `Objects/`には`.blend`だけを置く。`.glb`は`Out/`、スクリプトは`Scripts/`に置く。

### シーン管理

- プロジェクトのルートディレクトリにシーンごとの.blendファイルを配置する。
- 1ファイルに1シーンとする。
- シーンのマスターは1ファイルになるようにし、一時的なバックアップは`Tmp/`、試作は`PlayGround/`に配置する。
- 基本的には版管理でロールバックできるようにしてバックアップ用のファイルは生まない。

### アバター・リグ・アニメーション管理

- アバターは1つのオブジェクトとして扱い、`Objects/Avatar/Avatar.blend`をマスターとする。
- リグ（アーマチュアとIKコントローラ）とアニメーションもこのマスターの中で作る。
- **複数のモーションはアクションとして1ファイル内に持つ。** 切り替えはドープシートの
  Action Editor で行う。書き出しに載せたいアクションには必ずフェイクユーザー
  （盾アイコン）を付ける。付けないとファイルを閉じたときに破棄される。
- アニメーション作成に他のオブジェクト（机・椅子など）が必要な場合は、作業中だけ
  `Objects/`からリンクし、完成したら外してアバターだけが残る状態で保存する。
  座標を数値で持っておけば、書き出し自体には他オブジェクトは要らない。
- アバターのマスターにシーンの小道具を実体として取り込まない。

### スクリプト管理

- Blender で走らせるスクリプトはすべてリポジトリの`3DCG/Scripts/`に置く。
  iCloud 側の`Objects/`配下には置かない。
  （オブジェクト固有のものと共通のものが混在しており、2か所に分けると散乱するため）
- 用途ごとにサブフォルダへ分ける。`lib/` `Objects/` `Motion/` `Export/`。
- スクリプトから絶対パスを直接書かない。`Scripts/lib/paths.py`を経由する。
- 実行例は`Scripts/README.md`に置く。

### 出力成果物管理

- 次工程の入力になる成果物は`Out/`直下に配置する。
- 次工程で試しに使いたい場合などは`Out/Tmp/`に配置するが、これは削除されても良いものとする。
- ファイル名は snake_case とし、拡張子の前にスペースや日本語を入れない。
  - オブジェクト単体：`<object_name>.glb`（例：`wall_clock.glb`、`room_walls.glb`）
  - シーン：`<scene_name>_<releaseVersion>_<modelVersion>.glb`
    （例：`portfolio_room_1_1.glb`。サイトを初リリースしたときが`1_1`、
    機能追加なしで3DCGだけ更新したら`1_2`）
- `Out/`直下のファイルは、Webサイトの`public/`へコピーして使う。

### テクスチャ管理

- プロジェクト内すべてのテクスチャの編集は1ファイルで行う。
- 画像編集ソフトでは、オブジェクトごとのレイヤーをグルーピングして管理する。
- 編集用ファイルは`Textures/`直下に配置する。
- テクスチャ画像の対象ごとにフォルダを設け、その配下には`Albedo.png`や`Alpha.png`などの
  テクスチャ画像を配置する。
- 1つの画像に複数オブジェクトのテクスチャを詰め込むため、`Objects/`には配置しない。

### 参考資料の管理

- 参考資料はすべて`Reference/`に配置する。
- 適宜フォルダ分けする。
- モーションの参考動画も対象とする。何を根拠に作ったかを残すため。

### 版管理

- スクリプトとこのルール文書は git 管理する。
- **アセットは版管理しない。** iCloud Drive のファイル履歴に頼る。
  公開リポジトリに 3D モデルを置くリスクを避けた結果、ロールバックの手段は失っている。
  そのぶん、以下を守ってマスターが分からなくなる事態を防ぐ。
  - シーンのマスターは常に1ファイル。日付違いのコピーを作らない
  - 一時的な退避は`Tmp/`に置き、用が済んだら消す
  - 大きな変更の前は`Tmp/`に退避してから作業する
- 書き出し設定を変えたときは`Scripts/lib/glb_diff.py`で回帰を確認する。
  版管理が無いぶん、壊れていないことを毎回確かめる。
