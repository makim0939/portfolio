# コンタクトフォームの設定

`/contact` のフォームは、届いた内容を自分のメールに流すだけの作りです。
データベースは使っていません。やり取りの本体はメール側にあります（[Issue #72](https://github.com/makim0939/portfolio/issues/72)）。

## 環境変数

`.env.local` に3つ足すと動きます。1つでも欠けていると、本番では送信が失敗します。
開発中は欠けていてもエラーにならず、内容がターミナルに出るだけになります。

| 名前 | 中身 |
| --- | --- |
| `RESEND_API_KEY` | [Resend](https://resend.com) のAPIキー |
| `CONTACT_FROM_EMAIL` | 差出人。Resendで所有を確認したドメインのアドレス（例 `お問い合わせ <noreply@makimura.me>`） |
| `CONTACT_TO_EMAIL` | 自分の受信先。ここに届く |

差出人のドメインは、Resendの管理画面でDNSレコードを足して確認を通す必要があります。
確認していないドメインから送ろうとすると、送信そのものが弾かれます。

無料枠は月3,000通・日100通・確認済みドメイン1つまでです。

## 届いてからの流れ

1. 自分宛に1通届く。差出人は `CONTACT_FROM_EMAIL` だが、返信先は送信者本人に向けてある
2. **そのまま「返信」を押せば送信者に届く**。管理画面はない
3. 送信者がメールアドレスを書いていた場合は、控えが送信者にも1通届く

送信者がメールアドレスを書かなかった場合は、こちらから返信する手立てがありません。
その旨は送信直後の画面にも出しています。

## 迷惑メッセージ対策

普通に使う人には何も求めない範囲だけ入れています。

- 人には見えない入力欄（罠）が埋まっていたら受け取らない
- ページを開いてから3秒未満で送られたら受け取らない
- 同じ送信元から1時間に3通を超えたら断る

前の2つは、弾いたことを相手に伝えず、送れたときと同じ画面を出します。
数え方はサーバのインスタンスごとなので、増えたときは取りこぼします。
すり抜けられるようになったら、確認ステップを足すか、数える場所を外に出します。

## 変えたいとき

- 返信の目安や上限文字数は [`src/lib/contact.ts`](../src/lib/contact.ts) にまとめてあります
- メールの文面は [`src/lib/contactMail.ts`](../src/lib/contactMail.ts) です

## ポストの3Dモデル

送信すると封筒が投函される演出（[Issue #75](https://github.com/makim0939/portfolio/issues/75)）で使っています。

- マスターは 3DCG リポジトリの `Objects/Post/Post.blend`、生成スクリプトは `Scripts/Objects/Post.py`
- 書き出しは `blender -b -P Scripts/Objects/Post.py -- Out/post.glb Objects/Post/Post.blend`。
  `Out/post.glb` を `public/` へコピーします
- 寸法を変えたら [`src/lib/contactPost.ts`](../src/lib/contactPost.ts) の投函口の座標も直します。
  部屋の glb と `Room.tsx` が対になっているのと同じ関係です
- ふたは投函口の上辺に原点を置いてあるので、React 側は X 軸まわりに回すだけで開きます

演出はフォームの飾りとして切り離してあります。3Dが読み込めなくても送信はできます。
